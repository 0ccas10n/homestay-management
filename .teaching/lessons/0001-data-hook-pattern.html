Pattern của useBookings

Lesson 0001 · 15 phút · Custom hooks cho data fetching

Pattern là gì?

Mỗi resource trong app (Booking, Room, Customer, CleaningTask...) đều có một hook riêng: useBookings, useRooms, useCustomers, useCleaning... Tất cả đều tuân theo cùng một "hình dạng" — một data hook pattern.

Mở src/hooks/useBookings.ts và đọc lướt. Bạn sẽ thấy nó luôn trả về cùng 5 thứ:

{ bookings, loading, error, refetch, ...mutations }
  • bookings — mảng dữ liệu hiện tại
  • loading — true khi đang fetch
  • error — thông báo lỗi, hoặc null
  • refetch — hàm gọi lại để tải dữ liệu mới
  • Mutations: createBooking, updateBooking, cancelBooking

Tại sao pattern này tốt?

Khi bạn mở bất kỳ page nào (như Bookings.tsx), bạn biết chính xác cần gọi hook nào, destructure cái gì, và dùng refetch khi nào. Component chỉ tập trung vào render — fetch + state nằm hết trong hook.

Đây chính là triết lý của React docs: "hide the gnarly details of how you deal with some external system so your components express intent, not implementation." (Reusing Logic with Custom Hooks)

Ba quyết định thiết kế quan trọng nhất

1. Trả về object, không phải array

Hook trả về object có tên, không phải tuple:

// Cách viết của codebase:
const { bookings, loading, refetch } = useBookings();

// (Một số codebase khác dùng array — tuple — để ép thứ tự:
const [bookings, loading, refetch] = useBookings();

Object tốt hơn vì khi thêm field mới (ví dụ error) sẽ không phá code cũ. Tuple sẽ vỡ.

2. Optimistic update — sửa local ngay, không refetch

Trong useBookings.ts, hàm cancelBooking làm việc này:

const cancelBooking = useCallback(async (id: string) => {
  const res = await bookingsApi.updateStatus(id, 'cancelled');
  setBookings(prev => prev.map(b =>
    b.bookingId === id ? res.booking : b,
  ));
}, []);

Thay vì gọi lại refetch() để tải toàn bộ danh sách, hook sửa đúng một dòng trong state. Hai lợi ích:

  • UI cập nhật tức thì — không có flash "Loading…"
  • Tiết kiệm 1 round-trip tới server

Đánh đổi

Nếu mutation thất bại phía server (rất hiết), UI sẽ hiển thị trạng thái sai. Trong codebase, mutation thất bại sẽ ném exception để component bắt (catch) — nhưng state thì đã được sửa. Đây là "happy path" optimistic. Hãy để ý khi đọc Bookings.tsx dòng 76–85.

3. useCallback cho mọi hàm trả về

Tất cả hàm trong hook đều bọc trong useCallback với dependency []:

const refetch = useCallback(async () => { ... }, []);

Mục đích: ổn định identity. Khi component cha gọi refetch() trong useEffect, identity không đổi → effect không bị chạy lại. Nếu quên useCallback, mỗi render sẽ tạo hàm mới → effect loop vô tận.

Luồng dữ liệu khi mở Bookings page

Khi user mở /bookings, dữ liệu chảy như sau:

Browser load /bookings
       ↓
Bookings.tsx render
       ↓
useEffect → refetch() / refetchRooms() / refetchCustomers()
       ↓
useBookings → bookingsApi.get() → fetch('/api/bookings')
       ↓
API route → bookings.repository.ts → Google Sheets API
       ↓
Response envelope: { success: true, data: Booking[] }
       ↓
api.ts unwrap → return data
       ↓
setBookings(data) → re-render → bảng hiện ra

Mỗi tầng có một trách nhiệm duy nhất. Hook không biết Google Sheets. Repository không biết React. API route không biết validation Zod (xem lib/api/validation.ts).
